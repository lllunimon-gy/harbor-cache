# 文件和数据库之间没有一笔共同事务

put 写入 UUID.tmp，关闭写入后 rename 为 UUID.blob，再更新 SQLite 中的 key → file。
索引成功后才尝试回收旧内容。actor 中没有跨 I/O 的 await，操作之间不会因重入被穿插。
目录锁阻止第二个实例打开同一目录；这不是跨进程共享读写协议。

| 中断位置 | 重启后的行为 |
|---|---|
| tmp 写入中 | 旧索引仍有效，tmp 被回收 |
| blob 完成但索引未提交 | 旧值仍可读，新 blob 是孤儿 |
| 索引提交但旧文件未删除 | 新值可读，旧 blob 是孤儿 |
| 索引已删除但文件未删除 | key 不再可见，文件等待回收 |

重启先验证索引中的文件名、普通文件类型和长度，再清理未被引用的 UUID 内容文件。
不认识的文件保留。索引文件和内容目录不能是符号链接。正常应用沙箱内仍应保证没有其他代码改写本目录。
同长度的内容损坏不检测；如需要，应增加内容哈希，并测量读路径代价。

失败语义：contentWritten 后故障发生在提交前；indexCommitted 后故障意味着操作可能已成功。
公共 API 返回错误不能一概解释为“完全没写入”。重试同一个 key 是覆盖语义。
自动清理失败也可能发生在写入已成功之后。删除失败记录在 TrimResult，剩余物理占用在重启时继续回收。

单 key 访问使用主键查询，清理预览和恢复仍使用完整索引。
